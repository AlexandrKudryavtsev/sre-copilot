# Приёмка Monitoring Core — 8 октября 2026

Полный сценарий из раздела 40 `TASK_WITHOUT_AI.md` пройден в локальном Docker-окружении.
Проект и правило созданы через рабочий React UI. Подключение, включение мониторинга,
Dashboard, прогресс правила, карточка инцидента и итоговый статус проверены в Chrome.
Ответы API и прямой запрос PostgreSQL дополнительно подтвердили сохранение данных.

## Источник метрик

Отдельное временное приложение Spring Boot 4.1.1 с Web MVC, Actuator и
`micrometer-registry-prometheus`, подключённым согласно
[документации Spring Boot](https://docs.spring.io/spring-boot/reference/actuator/metrics.html).
Endpoint: `http://acceptance-service:8091/actuator/prometheus`, тип проекта — `ACTUATOR`.
Actuator отдавал `text/plain;version=0.0.4;charset=utf-8`.

Шесть параллельных HTTP-клиентов вызывали `/work`; примерно каждый десятый запрос
возвращал HTTP 500. В штатном режиме обработчик ожидал 35 мс, при нарушении — 1200 мс.
Исходные счётчики и длительности HTTP-запросов регистрировал Micrometer, CPU измерялся
для настоящего JVM-процесса. Значения Golden Signals не подставлялись генератором.
Контейнер тестового сервиса и клиент нагрузки были временными.

## Длительность инцидента

У открытого инцидента значение `Duration` росло в браузере каждую секунду.
После закрытия UI показал `Resolved`, время завершения и фиксированную длительность
`2m 30s`, вычисленную по `resolvedAt - startedAt`. Формат поддерживает секунды,
минуты, часы и дни, а отрицательная длительность при расхождении часов исключена.
