# Проверка backend с настоящим OpenAI API

Дата: 8 октября 2026 года, около 21:02 (Europe/Moscow).

## Сценарий

- Backend запущен из собранного JAR на отдельном порту с новой PostgreSQL 17.
- Токен прочитан из локального `.env` и передан только в окружение backend.
- API: `https://api.openai.com/v1/responses`, модель `gpt-4o-mini`.
- Локальный demo-service действительно отдавал Prometheus-метрики, которые собирал scheduler.
- После нескольких нормальных samples сценарий изменён на `overloaded`.
- Правило: `SATURATION >= 80`, severity `CRITICAL`, три последовательных нарушения.
- Инцидент создан автоматически Rule Engine, без ручной вставки в БД.
- AI автоматически получил контекст и выполнил настоящий HTTP-запрос к OpenAI.

## Результаты

- Автоматический анализ: `PENDING → COMPLETED`, ожидание после создания инцидента — 6.08 с.
- Ответ с probable cause, evidence и recommendations прошёл backend-валидацию и сохранён в PostgreSQL.
- Проверка БД: `COMPLETED:4:4` — статус и числа элементов evidence/recommendations.
- `POST /api/incidents/1/ai-analysis/retry`: HTTP 202, `PENDING → COMPLETED`; повторный настоящий API-запрос успешен.
- После возвращения demo-service в `normal` мониторинг автоматически перевёл инцидент в `RESOLVED`.
- Токен отсутствует в логах backend.
- Тестовые процессы и PostgreSQL-контейнер удалены; рабочая БД и `.env` не изменялись.
- После уточнения prompt полный `mvn verify`: 73 unit tests + 84 integration tests, без ошибок и пропусков.

## Качество выводов

В первом пробном ответе модель неточно описала динамику CPU и использовала неизвестную
аббревиатуру. Инструкции уточнены: сравнивать численные значения хронологически,
не вводить дополнительные метрики, отличать CPU процесса от других ресурсов.

В следующем автоматическом ответе модель всё же упомянула увеличение нагрузки на СУБД,
хотя предоставленные данные не содержали сведений о СУБД. Этот вывод не подтверждён
метриками и не должен приниматься как установленный факт. Повторный анализ сформулировал
гипотезу о росте трафика и CPU процесса.

Проверка подтверждает работу реального API, асинхронного запуска, persistence, REST и Retry.
Валидация JSON проверяет контракт ответа, но не гарантирует фактическую достоверность
каждой фразы. Выводы модели требуют проверки человеком; одного prompt недостаточно
для строгой гарантии отсутствия выдуманных фактов.
