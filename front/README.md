# SRE Copilot frontend

Рабочий frontend Monitoring Core на React, TypeScript и Vite. Согласованное оформление
сохранено: sidebar, карточки Golden Signals, таблицы инцидентов и графики Recharts.
Все данные рабочего интерфейса поступают из Spring Boot API.

## Запуск вместе с backend

Из корня репозитория:

```sh
docker compose up --build -d --wait
```

Откройте http://localhost:5173. Порт меняется через `FRONTEND_PORT` в корневом `.env`.
Frontend в контейнере отдаёт Nginx; `/api` проксируется на backend внутри Compose.

## Локальная разработка

Нужен Node.js 22.13+ и работающий backend:

```sh
# Из корня проекта:
docker compose up --build -d --wait backend demo-service
cd front
npm ci
npm run dev
```

Dev-server: http://localhost:5173. Vite проксирует `/api` на http://localhost:8080.
Если frontend уже запущен в Docker, сначала выполните `docker compose stop frontend`
из корня проекта, чтобы освободить порт 5173.
При другом адресе backend скопируйте `.env.example` в `.env.local` и задайте
`API_PROXY_TARGET`. Для отдельно размещённого API можно задать `VITE_API_BASE_URL`
как origin, например `https://api.example.com`; backend должен разрешать CORS для
origin интерфейса. Переменные Vite применяются при запуске dev-server или сборке.

## Первый проект

1. Откройте Projects → New project.
2. Укажите название и Prometheus endpoint `http://demo-service:8081/metrics`.
   Этот адрес используется backend в Docker. Для backend на хосте используйте
   `http://localhost:8081/metrics`.
3. Создайте проект и нажмите Test connection на Overview.
4. Включите Enable monitoring. Первая коллекция устанавливает базовую точку
   счётчиков, вторая сохраняет Golden Signals. По умолчанию интервал backend — 30 секунд.
5. Overview обновляет данные каждые 15 секунд. Можно выбрать период истории или
   нажать Refresh. Перезагрузка браузера не теряет проект и его данные.

## Что реализовано

- Список проектов, поиск, создание и редактирование.
- Проверка подключения с сообщением backend, включение/пауза мониторинга.
- Удаление с подтверждением, включая историю, правила и инциденты проекта.
- Overview: средняя latency, traffic, HTTP 5xx errors и CPU saturation; история
  за 1/3/6/24 часа. Пороговые линии берутся из включённых правил backend.
- Состояния загрузки, ошибок, пустой БД, отсутствия первых snapshots и недоступного
  источника. Старые значения отмечаются как исторические; при нулевом traffic
  latency/errors не выдаются за наблюдение здоровья.
- Список инцидентов с поиском и фильтрами. Детали включают исходное условие правила,
  четыре показателя при обнаружении и историю за 15 минут вокруг события.
- Длительность открытого инцидента обновляется каждую секунду; после восстановления
  вычисляется по `resolvedAt` и больше не растёт. Отображаются секунды, минуты, часы и дни.
- AI Analysis в деталях инцидента: вероятная причина, evidence, упорядоченные рекомендации,
  время анализа и предупреждение о необходимости проверки AI-выводов.
- Состояния AI: `PENDING`, `COMPLETED`, `FAILED`, `INSUFFICIENT_DATA`; для старых инцидентов
  без анализа — `No analysis yet` и кнопка `Analyze incident`.
- При `PENDING` frontend опрашивает backend каждые 3 секунды без пересекающихся запросов;
  после завершения и при уходе со страницы polling прекращается.
- `Retry Analysis` запускает анализ через backend. Двойной клик не создаёт повторный POST,
  ошибка запуска сохраняет прежний результат и показывает сообщение с повторной загрузкой.
- Настоящие статусы OPEN/RESOLVED; закрытие выполняет backend автоматически.
- Rules: создание и редактирование для четырёх Golden Signals, четыре оператора,
  severity, интервал и количество последовательных нарушений; включение/отключение,
  поиск и фильтр. Список показывает runtime state и ссылку на открытый инцидент.
- Удаление правила с подтверждением сохраняет историю закрытых инцидентов.
  При открытом инциденте удаление заблокировано; отключение приостанавливает recovery.
- Hash-навигация, прямые ссылки и Back/Forward.

Правила настраиваются на Overview → Manage rules или через раздел Rules в sidebar.
AI-запросы идут только через Spring Boot: `GET /api/incidents/{id}/ai-analysis`
и `POST /api/incidents/{id}/ai-analysis/retry`. OpenAI-токен во frontend не используется.
Ручное управление жизненным циклом инцидента не реализовано.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Тесты проверяют ответы 204, ProblemDetail, конфликт проверки подключения, отмену
запросов, выбранный период истории и условия правил. Также сохранены тесты исходного
демонстрационного набора данных. Тесты AI проверяют polling до конечного статуса,
остановку после завершения и навигации, отсутствие пересекающихся запросов, Retry,
отбрасывание запоздавших ответов и восстановление после временной сетевой ошибки.

## Структура

```text
src/
  App.tsx                 оболочка и навигация
  pages/                  Projects, Overview, Incidents
  components/             действия проекта, графики, таблицы, обратная связь
  hooks/                  отмена запросов, обновление данных
  lib/                    типы API, HTTP-клиент, сигналы и форматирование
components/ui/            базовые компоненты исходного дизайна
app/globals.css           стили согласованного макета
prototype/                исходный макет, сохранённый как справочный образец
lib/mock-data.ts           данные исходного макета; рабочий frontend их не импортирует
```

`prototype/` не входит в приложение или Docker-образ. Старые служебные каталоги
Sites/Vinext/Cloudflare не используются и игнорируются при сборке.
